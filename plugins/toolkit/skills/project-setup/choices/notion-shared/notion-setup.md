# Notion: the steps that work items and memory share

Follow these steps when [choices/work-items/notion/notion-work-items-setup.md](../work-items/notion/notion-work-items-setup.md) or [choices/memory/notion/notion-memory-setup.md](../memory/notion/notion-memory-setup.md) sends you here. The job is done when the owner is signed in, the project's Notion pages were made only after the owner's yes, and `PROJECT.md` holds the project's Notion links and ids.

## Steps

Do step 1 right after the owner picks Notion, before the next question of the guide, [SKILL.md](../../SKILL.md). Do steps 2 to 5 when the owner's sign-in is done and the owner has answered questions 5, 6, and 7 of the guide. When work items and memory are both in Notion, both setup files send you here, and you do each step once.

1. **Ask the owner for the Notion sign-in, and check it.** Ask as soon as the owner picks Notion, so that the owner can sign in while the interview goes on. `ntn whoami` checks the sign-in. [reference/notion-sign-in.md](reference/notion-sign-in.md) says what the owner does, and what to do when `ntn` is not installed or a call cannot reach a page.
2. **Tell the owner what will be made in Notion, and get the owner's yes.** [reference/what-setup-may-do-in-the-owners-notion.md](reference/what-setup-may-do-in-the-owners-notion.md), "The owner's yes before anything is made", gives what to tell the owner, what the yes covers, what to do when the owner has no "Project" template, and what to do for a test project. The same file lists the only Notion calls that setup makes apart from the calls of step 4.
3. **Confirm which Projects database gets the project's row.** [reference/where-the-notion-project-page-goes.md](reference/where-the-notion-project-page-goes.md) gives the call that finds the database, the question, and what to do when the owner names a page or has no Projects database.
4. **Make the project's pages from the owner's "Project" template.** Every Notion project is made from the one Projects database template, "Project", which holds both the work items part and the memory part. So follow [reference/notion-project-pages.md](reference/notion-project-pages.md), "A new project", whether the project keeps work items, memory, or both in Notion. That section makes the project page, asks the owner about the ID prefix when work items are in Notion, removes the part this project keeps elsewhere, and runs the memory steps in [reference/notion-memory-pages.md](reference/notion-memory-pages.md) when memory is in Notion.
5. **Write the links and ids in `PROJECT.md`, and read them back.** With memory in Notion, also put the id of the "Current state" page in the settings files. [reference/where-the-notion-links-and-ids-go.md](reference/where-the-notion-links-and-ids-go.md) says where each line goes and how the page's id gets into the session-start hook.

For an existing project, "update the toolkit" follows the reviewed migration procedure. [reference/updating-a-notion-project.md](reference/updating-a-notion-project.md) says what to tell the owner in an update.

When a project that has work items or memory in Notion adds the other one, follow [reference/notion-project-pages.md](reference/notion-project-pages.md), "Adding work items or memory later". The checks for "check the setup" are in the same file, under "Checks after any of these". [reference/update.md](../../reference/update.md) says how each of those jobs works.
