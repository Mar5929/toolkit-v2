# A Salesforce project

Follow these steps when the owner answers yes to question 7 of the guide, [SKILL.md](../../SKILL.md). The job is done when all of these are true: the Salesforce files are in the project; `PROJECT.md` holds the org aliases; `.claude/settings.json` holds the refuse list entries, and the entries that match the production cells of the owner's file for each production org that the owner named; the API version is written in the two files that hold it; the owner knows when Salesforce's skills are not installed; and the owner has said what to have on or off.

## Steps

Do steps 1 to 10 right after the answer, before the next question of the guide. Do steps 11 to 14 when setup finishes, in Step 6 of the guide.

Ask one question per message. Setup only reads orgs (`sf org list`, `sf org display`). Never run a deploy, a data command, or anything that changes an org during setup. Where the owner cannot give a value yet, the file that the step names says what to write in its place.

1. **Tell the owner how the toolkit sets up a Salesforce project by default, and ask whether that is what the owner wants.** [reference/salesforce-default.md](reference/salesforce-default.md) holds the default. [SKILL.md](../../SKILL.md), "Each choice has questions of its own", gives the words of the question and what to ask after a no.
2. **Ask whether the defaults for what an agent may do in each kind of org are what the owner wants.** The table "Actions" in the rule `.claude/rules/salesforce-agent-permissions.md` holds every default. Until step 6 copies the rule into the project, read it in `choices/salesforce/files-to-add/`. Step 8 writes each change.
3. **Show the owner the org aliases on this computer, and ask which sandbox the agents may deploy to, which org is production, and which orgs agents may only read.** [reference/salesforce-org-aliases.md](reference/salesforce-org-aliases.md) gives the command that shows the aliases, the three questions, and what to do when none of the project's orgs is on this computer yet.
4. **Check that Salesforce's own skills are installed, and ask the owner which of them to have on or off.** [reference/salesforce-own-skills.md](reference/salesforce-own-skills.md) says where the skills come from, how to check them, and what to ask. Tell the owner what is missing, and change only what the owner says. Setup installs none of them.
5. **Find the project's API version.** Read it from the sandbox that the owner named in step 3, and ask the owner when it cannot be read. [reference/salesforce-api-version.md](reference/salesforce-api-version.md), "Find the version", gives the command, the orgs it may never run against, and what to do when the owner does not know the version yet.
6. **Copy the choice's files into the project.** The folder `choices/salesforce/files-to-add/` holds them at the paths a project has them. [reference/what-salesforce-adds-to-a-project.md](reference/what-salesforce-adds-to-a-project.md) lists them, and [reference/placing-files.md](../../reference/placing-files.md) gives the copy command and what to do with a file that the project already has.
7. **Write the choice's lines in `AGENTS.md`, `PROJECT.md`, and `.gitignore`.** [reference/what-salesforce-adds-to-a-project.md](reference/what-salesforce-adds-to-a-project.md) gives each line and the place where it goes. [reference/salesforce-org-aliases.md](reference/salesforce-org-aliases.md), "The aliases line in PROJECT.md", gives the form of the line that holds the aliases from step 3.
8. **Write each change that the owner wants to what an agent may do in an org.** The changes are the owner's answer in step 2 and each instruction about an org that the owner gave in step 3. Write each one into the project's `.claude/rules/salesforce-agent-permissions.md`, in the place that the first bullets of that file give.
9. **Add the refuse list entries to `.claude/settings.json`.** [reference/salesforce-refuse-list.md](reference/salesforce-refuse-list.md) gives the six entries that every Salesforce project gets, the entries for each production org and read-only org that the owner named, and the line to tell the owner. [reference/skills-hooks-settings.md](../../reference/skills-hooks-settings.md), "Merge rules", gives the rules for a settings file that the project already had.
10. **Write the API version in the two files that hold it.** [reference/salesforce-api-version.md](reference/salesforce-api-version.md), "Write the version", names the two files, and the two templates that keep `XX.0`.
11. **Record each thing that the owner still has to do, as a "Waiting on" line in the project's Current State.** [reference/salesforce-steps-left-for-the-owner.md](reference/salesforce-steps-left-for-the-owner.md), "How setup records what is still open", says which lines a Salesforce project needs. A Hindsight project has no Current State: there, write each one as a project task, as that file says.
12. **Check the refuse list and data-file exclusions.** `jq '.permissions.deny' .claude/settings.json` lists the six entries that every Salesforce project gets, and the entries for each read-only org and those that match the production cells for each production org that the owner named. [reference/salesforce-refuse-list.md](reference/salesforce-refuse-list.md) gives the entries, and [reference/finishing.md](../../reference/finishing.md), "Final checks", says how to run a check and what to do when one fails.
   Put a test `.csv` file in `delivery/migrations/production-backups/` and in `delivery/migrations/data-loads/`. Check that `git status` lists neither, then delete both test files.
13. **Tell the owner the steps that only the owner does.** [reference/salesforce-steps-left-for-the-owner.md](reference/salesforce-steps-left-for-the-owner.md), "The owner's own steps", gives the two steps of a Salesforce project. [reference/finishing.md](../../reference/finishing.md), "The owner's steps", says how to tell the owner a step.
14. **Name in the report what is still open.** [reference/salesforce-steps-left-for-the-owner.md](reference/salesforce-steps-left-for-the-owner.md), "How setup records what is still open", says what the report lists for a Salesforce project. [reference/finishing.md](../../reference/finishing.md), "The report", gives the parts of the report.

"Check the setup" and "update the toolkit" use the same steps: steps 6, 7, and 9 give the folder, the lines, and the settings entries that this choice adds, and step 12 gives its check. [reference/update.md](../../reference/update.md) says how each of those jobs works.
