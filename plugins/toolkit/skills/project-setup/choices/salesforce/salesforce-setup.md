# A Salesforce project

Follow these steps when the owner says this is a Salesforce project. The job is done when all of these are true: the Salesforce files are in the project; `PROJECT.md` holds the org aliases; `.claude/settings.json` holds the refuse list entries, and the entries that match the production cells of the owner's file for each production org that the owner named; the API version is written in the two files that hold it; the owner knows when Salesforce's skills are not installed; and the owner has said what to have on or off.

## Steps

Do steps 1 to 10 right after the answer, before the next interview question. Do steps 11 to 14 when setup finishes.

Ask one question per message. Setup only reads orgs (`sf org list`, `sf org display`). Never run a deploy, a data command, or anything that changes an org during setup. Where the owner cannot give a value yet, the file that the step names says what to write in its place.

1. **Tell the owner how the toolkit sets up a Salesforce project by default, and ask whether that is what the owner wants.** [reference/salesforce-default.md](reference/salesforce-default.md) holds the default.
2. **Ask whether the defaults for what an agent may do in each kind of org are what the owner wants.** The table "Actions" in the rule `.claude/rules/salesforce-agent-permissions.md` holds every default. Until the rule is copied into the project, read it in `choices/salesforce/files-to-add/`. Step 8 writes each change.
3. **Show the owner the org aliases on this computer, and ask which sandbox the agents may deploy to, which org is production, and which orgs agents may only read.** [reference/salesforce-org-aliases.md](reference/salesforce-org-aliases.md) gives the command that shows the aliases, the three questions, and what to do when none of the project's orgs is on this computer yet.
4. **Check that Salesforce's own skills are installed, and ask the owner which of them to have on or off.** [reference/salesforce-own-skills.md](reference/salesforce-own-skills.md) says where the skills come from, how to check them, and what to ask. Setup installs none of them.
5. **Find the project's API version.** [reference/salesforce-api-version.md](reference/salesforce-api-version.md), "Find the version", gives the command, the orgs it may never run against, and what to do when the version cannot be read.
6. **Copy the choice's files into the project.** [reference/what-salesforce-adds-to-a-project.md](reference/what-salesforce-adds-to-a-project.md) lists them.
7. **Write the choice's lines in `AGENTS.md`, `PROJECT.md`, and `.gitignore`.** [reference/what-salesforce-adds-to-a-project.md](reference/what-salesforce-adds-to-a-project.md) gives each line and the place where it goes. [reference/salesforce-org-aliases.md](reference/salesforce-org-aliases.md), "The aliases line in PROJECT.md", gives the form of the aliases line.
8. **Write each change that the owner wants to what an agent may do in an org.** The changes are the owner's answer in step 2 and each instruction about an org that the owner gave in step 3. Write each one into the project's `.claude/rules/salesforce-agent-permissions.md`, in the place that the first bullets of that file give.
9. **Add the refuse list entries to `.claude/settings.json`.** [reference/salesforce-refuse-list.md](reference/salesforce-refuse-list.md) gives the six entries that every Salesforce project gets, the entries for each production org and read-only org that the owner named, and the line to tell the owner.
10. **Write the API version in the two files that hold it.** [reference/salesforce-api-version.md](reference/salesforce-api-version.md), "Write the version", names the two files, and the two templates that keep `XX.0`.
11. **Record each thing that the owner still has to do.** [reference/salesforce-steps-left-for-the-owner.md](reference/salesforce-steps-left-for-the-owner.md), "What setup records as still open", says which items a Salesforce project needs. Record each one where the memory choice's `reference/finishing-memory-setup.md` records open owner steps.
12. **Check the refuse list and the data-file exclusions.** `permissions.deny` in `.claude/settings.json` lists the six entries that every Salesforce project gets, the entries for each read-only org, and those that match the production cells for each production org that the owner named. Git ignores a `.csv` file in `delivery/migrations/production-backups/` and in `delivery/migrations/data-loads/`.
13. **Tell the owner the steps that only the owner does.** [reference/salesforce-steps-left-for-the-owner.md](reference/salesforce-steps-left-for-the-owner.md), "The owner's own steps", gives them.
14. **Name in the report what is still open.** [reference/salesforce-steps-left-for-the-owner.md](reference/salesforce-steps-left-for-the-owner.md), "What setup records as still open", says what the report lists.
