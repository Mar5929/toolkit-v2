# Reconcile the wiki destinations

Project Wiki is the parent navigation page. Current state and Long-Term Memory are pages; Wiki Inbox, Terminology Glossary and Product Wiki are databases. Long-Term Memory contains the five existing collections. Preserve these distinctions when traversing.

| Destination | What belongs there |
| --- | --- |
| Current state | A concise derived view of current priorities, workstreams, ownership, blockers and resumption context. The work tracker owns work status. |
| Long-Term Memory | Lasting project-specific context, non-product decisions, lessons and useful pointers that no other record owns. Retain only information that matters to later work and comes from the owner or work with the owner. |
| Terminology Glossary | Established project meanings, contextual distinctions, aliases and naming history. Tentative meanings stay in working records. |
| Product Wiki | Finalized architecture, product decisions with rationale, and documented behavior. Working designs stay in the work item. Documentation approval and implementation evidence remain separate. |

Read related records and sources before filing. Update the existing subject or system-area document when appropriate. Link the authoritative home rather than duplicating its content. One capture may update several destinations; preserve each verified destination link.

Keep product decisions with relevant Product Wiki documentation. Keep other durable decisions in Long-Term Memory. This Notion model maintains no duplicate local DECISIONS.md ledger, system specification or terminology glossary. Code and tests remain implementation evidence, not proof that a proposed design was approved.

For Current state, read the whole page and current tracker records. Reconcile its existing sections, remove resolved snapshot context, retain useful resumption information and update its date, sources and editor. Preserve history in source records rather than turning the snapshot into a log. Pending captures may describe more recent work than the snapshot.

For long-term collections, Memories holds durable subject records; Topics groups subjects; Entities and Facts provide useful named-thing or dated-statement retrieval when needed. Maintain their existing relationships and avoid creating copies of the same claim merely to fill every collection.
