# Maintain existing wiki content

Keep current wiki records and navigation useful even when Wiki Inbox has no new captures. Use the same project scope, writer coordination, schemas and verified-write procedure as filing. Choose maintenance scope from affected subjects, known problems and unfinished work; review more broadly when needed without requiring a full scan every run.

1. Read relevant existing destinations, pending captures and authoritative sources. Follow linked records and inspect their current status before treating similar content as duplicate or outdated.
2. Reconcile stale, contradictory or misplaced information using destination rules and record maintenance. Retain uncertainty when sources cannot resolve it. Preserve useful history, provenance and approvals; age alone does not make a record false.
3. Consolidate duplicated current content in its authoritative home. Preserve distinct context and supporting sources, replace repeated content with useful links, and update incoming pointers before retiring a redundant record. Historical versions and derived Current state summaries are not competing authority.
4. Check navigation and source links within the maintenance scope. Repair a pointer only after verifying its target; distinguish unavailable access from a missing record and keep unresolved references visible for recovery.
5. Read changed records and links back. Record unfinished maintenance, verified destinations and the next recovery step in the configured run record. Follow run coordination for owner escalation; routine maintenance stays quiet.
