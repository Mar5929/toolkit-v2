# Maintain evidence, metadata and history

Read the destination's fields and body before each change. Apply the live schema and preserve useful sources, relationships, owner edits and unrelated values. Capture and filing do not authorize new policy, unresolved decisions or unverified implementation claims.

## Metadata

Keep created and modified dates, actual editor, provenance, tags, context, derivation, type and replacement links accurate. Use native fields where they represent the meaning; use a compact labeled body section for missing metadata rather than changing databases without approval. Native last-edited fields identify the write time but do not replace a source date or human approval.

In Memories, retain the existing Toolkit mapping: Saved is last modification; Source note holds dated provenance; Other fields JSON holds modified_by, context, source_kind and extra retrieval tags; Tags includes the record type; Authorization states existing approval or librarian filing authority. Preserve created time, Source origin, Author and Agent creation attribution. Maintain Record Key and Keywords when creating a keyed record; existing unkeyed records remain searchable. Use Supersedes and Superseded by for reciprocal replacement links. Use Last verified only when the source was checked and Review By when time-sensitive evidence needs review. Fill missing history only from evidence; mark unavailable history unknown.

For Product Wiki, preserve existing Approved by and Approved on evidence, maintain Source, Related documentation and review dates, and set Documentation status independently from Implementation status. For Glossary, maintain Source, Last checked, contextual meaning and naming history. For Current state, maintain its update date, editor and supporting links. Preserve meaningful provenance in each affected record.

## Corrections and replacements

For ordinary corrections or added detail, update the existing record coherently and refresh metadata. Do not leave contradictory current guidance beside it. Check other current destinations and pending captures for the changed claim.

When a decision or fact is superseded, retain dated history and reciprocal links to its replacement. If other content remains current in the old record, mark the replaced section and leave that record current. For whole-record replacement, mark the old Memories record superseded, Product Wiki documentation Deprecated, or glossary term Retired as applicable. Link both sides, redirect current guidance and verify each affected record. Preserve historical sources and approval evidence.

Keep proposed or inferred material visibly uncertain. Set a record accepted or documentation Approved only from actual authorization or evidence permitting that status. Set implementation Live only when verified implementation evidence supports it. Librarian filing is not the approver.

## Forgetting and security

For an explicit forgetting request, find relevant destination content and pending captures, remove the unwanted content from accessible records and verify the result. Do not copy the forgotten content into another destination or processing notes. Retain only non-content audit details needed to state the operation's result. Preserve unrelated material; clarify an ambiguous scope before deleting a whole record.

Remove secrets and security-compromising information without repeating it in reports or recovery notes. A Notion page moved to trash is not proof of permanent deletion from history or backups. Report any limit on the requested forgetting accurately.
