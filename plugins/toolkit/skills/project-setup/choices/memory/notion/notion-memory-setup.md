# Set up the Notion Project Wiki

Follow these steps when the owner chooses Notion memory. The project is ready when its existing or newly copied Project Wiki is connected, its coding-agent and librarian skills are installed, its identifiers and operating settings are recorded, and retrieval and verified capture work.

When an existing project needs migration, prepare the new files in a setup copy and use the reviewed batch procedure in [update guidance](../../../reference/update.md) before replacing active Notion instructions, record routes or settings. Preserve the installed procedure until the approved destinations and moved records are verified; then continue setup.

1. Explain [the default Project Wiki](reference/notion-memory-default.md) and confirm the owner's project-specific changes using the setup interview.
2. Copy this choice's `files-to-add/` and `choices/notion-shared/files-to-add/` into the project. Do not copy the local memory process. [What the choice adds](reference/what-notion-memory-adds-to-a-project.md) gives the files and settings.
3. Record Memory as `notion` in `PROJECT.md`. Follow [Notion setup](../../notion-shared/notion-setup.md) for access and the owner's confirmed project/template destination. Reuse an existing Project Wiki rather than creating a duplicate.
4. After the owner authorizes the external setup, follow [Notion project pages](../../notion-shared/reference/notion-project-pages.md) and [Notion memory pages](../../notion-shared/reference/notion-memory-pages.md) to discover the Wiki Inbox, four destinations and long-term collections, verify schemas and relation targets, and record the identifiers. Preserve owner records and customized content.
5. At the finish of setup, use `maintaining-notion-wiki` on demand to initialize Current state from confirmed project context and current work records. Set its page ID in both hosts' session-start settings. Follow [finishing setup](../../../reference/finishing.md) for shared checks.
6. Select a supported daily librarian scheduler with the owner and record its access, invocation, coordination and failure handling in the Librarian schedule setting. Verify that it can invoke `maintaining-notion-wiki` and that on-demand operation works. If scheduling is unavailable, record the open setup step and retain on-demand operation. [The default](reference/notion-memory-default.md) gives the operating expectations.
7. Verify project-scoped retrieval, capture and read-back, librarian destination access and relation targets. Test a permitted representative capture and filing operation without modifying the template or unrelated records. Verify the session-start command can print Current state and that both hosts can discover the two delivered skills.
8. When work items are not in Notion, fill the project row’s Desired Outcome from the owner’s confirmed sentence and list its unanswered Project brief prompts in the setup report, as [finishing setup](../../../reference/finishing.md) describes. Report what was configured, verified and still open. [Known problems](reference/notion-memory-known-problems.md) gives recovery guidance.

For any existing project, propose a review and migration batch. Use [update guidance](../../../reference/update.md) for its approval, preservation and verification. Updating instruction files does not itself authorize a Notion migration or enable a schedule.
