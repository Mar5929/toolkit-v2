# Set up Hindsight as a project's memory

Follow these steps, in order, when the owner chooses Hindsight. Setup is done when the project reaches the intended bank, its settings and missions match the owner's choices, and the checks pass in each intended host. Use Hindsight's existing tools and configuration; add no setup scripts. Steps 1 to 3 are the interview with the owner; the later steps apply the answers and check the result.

## Steps to set up Hindsight for a project

1. **Confirm the connection and the bank.** Check the server, the installed add-on, the connection settings without exposing the key, and the project's recorded bank. Agree the bank's scope and stable ID with the owner, and read an existing bank's settings before proposing changes. [The connection and bank reference](reference/hindsight-connection-and-bank.md) holds the server addresses, the safety rules for every step, and the bank-choice rules. When the shared service is new or has changed, also check it against [the service settings](reference/hindsight-server-settings.md); otherwise skip that check.
2. **Offer the default settings and record the answer.** Explain what [the default package](reference/hindsight-package-default.md) does and what it costs, and ask whether the owner wants it or changes for this project. Record the answer.
3. **Offer the missions template and show the result.** Offer the Toolkit coding-project instructions, changes to them, or another template, as [the template for the project](reference/hindsight-template-for-the-project.md) says; the mission text is in [the recommended missions](reference/hindsight-missions-recommended.md). Show the resulting missions and any template settings before applying them.
4. **Add the project's files and the repository records.** Show changes outside the project before making them. Install the memory skill and rule, write the "Project memory" section of the root `AGENTS.md`, wire the reminder, and record the approved choices, as [what Hindsight adds to a project](reference/what-hindsight-adds-to-a-project.md) says. Copy `choices/memory/repository-records/files-to-add/` and write its rows, as [what the repository records add to a project](../repository-records/reference/what-repository-records-add-to-a-project.md) says.
5. **Prepare the add-on with capture off.** Write the connection settings and this project's bank settings with `retainSessions` and `codebaseSurvey` off before enabling the project's path or installing hooks. Have the owner enter a missing key privately in their Terminal. Inspect existing hook and MCP registrations, keep one approved integration per host, and install the add-on for Claude Code and Codex with the owner's server named. Apply the startup deadline and the Codex context allowance from the default package. The installed add-on has known bugs that this setup patches by editing the add-on's own JavaScript, as [the known defects](reference/hindsight-known-defects.md) describes. Before patching, ask the owner whether to first check if a newer Hindsight release fixes them and try it without the local patch; patch only what is still broken. Then have the owner trust changed Codex hooks with `/hooks`.
6. **Configure the bank and apply the missions.** Validate the approved bank configuration with Hindsight's template dry run, then create or configure the bank, preserving an existing bank's content and unrelated settings. Map the main checkout to the bank. Have the add-on prepare its strategies and pages, then apply the approved missions to the effective strategies as [the template for the project](reference/hindsight-template-for-the-project.md) says. Start a new session when the session's Hindsight tools still use old connection settings.
7. **Verify protections, then turn capture on.** Read back the effective bank and add-on settings, try representative extraction with the server's non-storing preview, and check that every proposed writer, including a code survey, excludes forbidden text from the whole submitted document before storage. Check any approved filter with safe dummy input. [The memory-flow verification](reference/hindsight-verification.md) gives these checks. Turn on the approved capture settings only after they pass, and keep a writer off when its protection cannot be verified.
8. **Verify in a new session in each host and report.** In a new Claude Code session and a new Codex session, run the host checks in [the memory-flow verification](reference/hindsight-verification.md) and the wiring check in [what Hindsight adds to a project](reference/what-hindsight-adds-to-a-project.md), "Verify the project wiring". When a check needs a saved sample, agree on it with the owner first. Report what passed and what remains, including any applied patch's maintenance and rollback. Mark setup done only when the checks pass.

## When preparation cannot finish

Keep capture off for a new setup and record where to resume as a project task. On an existing installation, keep working settings until their replacements are verified.

## Check, update, or connect a new computer

Read the recorded choices first and reuse the owner's decisions.

- For "check the setup", inspect and report without changing anything.
- For "update the toolkit", compare the project's memory skill and rule, the add-on's tool guidance, and the effective retain instructions with the current toolkit text. Show relevant differences and apply approved changes, preserving owner customizations and unrelated settings. Update effective extraction strategies as [the template for the project](reference/hindsight-template-for-the-project.md) says.
- For a new computer, apply and verify any missing approved configuration, including the add-on patches in [the known defects](reference/hindsight-known-defects.md) that are still needed. Memory stays on the server. Open the recorded bank link for the dashboard; its access key is separate from the API key.
