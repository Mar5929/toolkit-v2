# Verify the Hindsight memory flow

Use this before marking setup complete or accepting a configuration change. Verify the owner's approved behavior through the installed hosts, and record failed or unavailable checks as open work.

## Check preparation and processing

Read back the effective connection, bank identity, missions, extraction strategies, capture settings, security protection, and page configuration. File settings can differ from a running client's settings; restart the relevant session when required. Use the installed diagnostic tools and supported server APIs without exposing credentials or private source text.

Check representative extraction with a non-storing preview. Compare extracted and consolidated claims with their source for uncertainty and approval status, not only whether the right subjects were selected. Retrieved observations can preserve obsolete proposals. Preserve the setup's security checks on the whole submitted document for every writer; an extraction preview does not prove that a stored document is scrubbed. Keep a new writer disabled until its protection is verified.

When storage is needed for a check, agree on the sample with the owner. Verify successful processing and retrieval of the intended evidence. Check a deliberate Reflect answer for completeness, provenance, uncertainty, and consistency with confirmed owner choices. Recall and health alone do not prove that provider-authenticated extraction and synthesis work.

## Check the actual hosts

Start a new interactive session in each intended host, including Claude Code and Codex when both are configured. Verify hook trust, effective bank routing, and the generated startup reflection within the host deadline. Compare the complete hook output with the context actually delivered to the agent; host clipping is a separate failure from an incomplete API answer. Inspect diagnostics to distinguish successful reflection from fallback. A normal hook exit or pages response is not a successful generated startup summary.

Check the Codex Hindsight handler's native `additionalContextLimit: 5000` starting allowance and the loaded memory rule in both hosts. When a host supplies a preview and saved-file path, verify that the agent actually reads the complete file before answering. Allow normal file tools in this check; a tool-free diagnostic cannot exercise saved-output recovery. Review the complete answer against current project settings so historical proposals are not mistaken for live configuration.

Use representative prompts and check behavior while expected background work is active. Inspect complete answers as well as timing; source dates and approval status can be wrong even when the response is useful. A direct provider test, isolated engine, or manually invoked hook bundle is a narrower check and does not prove interactive host scheduling or trust.

Keep `reflectTimeoutMs: 90000`, `injectTimeoutMs: 15000`, and the 120-second first-message hook unless the owner approves different behavior. The fallback budget is shared by page search and recall after a reflection failure. These are deadline allowances, not expected response times or a latency fix. Recheck host entries after installing the add-on.

## Check surveys and knowledge pages

Verify the approved survey behavior and seeded page subjects without treating generated content as reviewed documentation. Check page source queries, scope, refresh schedule, last successful build, stale state, failure records, and background operation status. Review generated claims against current project records when they may have changed.

A configured schedule does not prove that refresh runs or recovers after failure. After an approved recovery, verify completed processing and page readback, then verify a later scheduled run before claiming automatic recovery. Check the installed server's retry and pause behavior. Preserve each page's approved source, scope, and schedule; report duplicate-looking subjects before proposing removal.

Page refresh uses its trigger's retrieval settings; ordinary bank `reflect_default_options` do not configure page builds. Inspect the effective trigger before changing page retrieval behavior.

## Record the result

Record what passed, which path was exercised, and what remains under `PROJECT.md`'s Hindsight setup entry and the corresponding work item. Distinguish installed interactive checks from narrower diagnostic tests. Keep setup open when a required behavior remains unverified. Use [known problems](hindsight-known-problems.md) to investigate a failure while preserving the approved package.
