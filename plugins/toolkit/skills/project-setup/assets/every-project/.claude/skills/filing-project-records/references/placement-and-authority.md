# Placement and authority

The root `AGENTS.md` gives the project map. Read the named destination
before writing. "Knowledge" means all useful project information; it is
not a folder or a separate save instruction.

| Information | Authoritative home | Project-wide record's job |
| --- | --- | --- |
| Original transcript, document, or other source | One existing source location assigned by the project and chosen tracker | Intake receipt links to that stable source; it holds findings, not a second copy |
| One item's requirement, question, answer, design, task, or status | That item in the chosen tracker | Link it when another item depends on it |
| Accepted behavior maintained after delivery | `requirements/` | Domain map points to it |
| Verified current system structure | `system-guide/` | Domain map points to it |
| Direction several items may build toward | `project-wide-records/target-architecture/` | State whether proposed, owner-approved, or superseded; do not describe it as delivered |
| One shared open question and its incorporation checks | `project-wide-records/questions/` | Coordinate the question; point to the authoritative answer |
| Lasting, selected decision or context | The project's chosen memory system | Link its source; do not copy an active question or a full design into memory |
| Current work and next session | Work item Current state and project Current State | Point to a shared question only while it blocks active work |

The item Questions and Answers row owns an answer given while working that
item. A project-wide decision with no work item follows the root
`AGENTS.md` decision and memory route. A shared question never grants
approval. Requirements approval stays with `running-work-item-lifecycle`.

For an existing project, search established architecture, stakeholder,
question, and source locations first. Do not move or copy a record merely
to fill the new folder. Decide which location is authoritative, link it,
and raise any conflict with the owner before changing that authority.
