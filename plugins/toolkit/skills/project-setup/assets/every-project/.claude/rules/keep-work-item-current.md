# Keep the Active Work Item Accurate

While you work an item, keep its whole record true, not only its Current state: each task's status and who does it, each phase's status, and every field you have information for.

## Current state

- Each work item's Overview holds its Current state: five lines (Where it stands, Next action, Waiting on, Blockers, Last updated) that say where the item stands now.
- After each step (a task finished, a question asked or answered, a State or `waiting_on` change, a pause), rewrite those five lines in place.
- Never add a line or a dated entry to Current state; write what happened as a new Recent History row.
- Keep each Current state line to one or two sentences.
- Write Next action in one of these three forms.
  - Working: `<Who>: <the exact next step, one sentence>.` For example: "Agent: write two design options for the permission set groups."
  - Waiting: `Waiting on the owner: Q-07 (<the question in a few words>). After his answer: <step>.` For example: "Waiting on the owner: Q-07 (merge or move the 15 personas). After his answer: finish R-04."
  - Finished or cancelled: `None. Finished.` or, for a cancelled item, `None. Cancelled.`
- When the item waits on the owner, use the waiting form with the first open question.
- The item's fields win when they disagree with Next action: when its status, State, `waiting_on`, approvals, or ticked tasks say something else, rewrite Next action to match them.

## Questions and decisions

- Save a bulk "yes to all" as one row for each thing it approved, each with the reason the owner was shown ("reason shown: none" when there was none).
- Save the owner's requirements and corrections in the item or its linked document before moving on.

## Approvals

- Moving an item to a later State does not revoke its requirements approval.

## Before you stop

- Before ending unfinished work, rewrite the item's Current state so its Next action names the exact next step.
