# Functional requirements

Keep one maintained file per durable business area, following `AREA-TEMPLATE.md`. `SYSTEM-DATA-MODEL.md` is the area file for the system's data model. Record agreed functional behavior and its conditions, exceptions, and source. The active work item owns proposed changes, open questions, detailed tasks, and execution history.

Update an area file at stage `14-spec-update`, after the owner approved the result and the delivery is confirmed. Approved behavior that has not shipped stays in the work item. Refer to work items and decisions by ID (a work item ID, or a `DECISIONS.md` ID); do not copy their task history here. Publish each update with the `publish-docs` skill.
