# Local Work-Item Folders

This project tracks work in local folders under `.work-items/`. The folder is
Git-ignored, lives in the main checkout, and is shared by every worktree. It is
not backed up by Git: `toolkit export` is the backup.

## An item is found by its ID, not its path

- An item is a folder holding a record, `WORK-ITEM.md`, and `DESIGN.md` when a
  design exists. The frontmatter `id` (for example `{{tracker.idPrefix}}-12`) is the item's
  identity. The folder name and the file name may change.
- Refer to items by ID everywhere. Find an item's files with
  `toolkit work show <id> --path`. Never guess a path.
- Create items only with `toolkit work new`. It takes the next ID under a lock,
  so parallel sessions never pick the same one. IDs are never reused.

## The owner may move folders, and the agent adapts

- The owner may move, rename, nest, or group item folders by hand. That is
  normal. `toolkit work sync` finds every item again by its ID; the session
  hooks and every `toolkit work` command run it. Report what moved and continue.
  Use the `work-organize` skill to reconcile anything the sync reports as
  missing or duplicated.
- A record inside another item's folder is that item's sub-item: its `parent`
  follows its location. A plain folder with no record is a group and changes no
  parent.
- `archive/` is a reserved group. Items there are hidden from the briefing and
  from `toolkit work next`.
- Never move, group, archive, or rename items on your own initiative. When the
  owner asks, use `toolkit work move <id> --under <id|group|archive|root>`.

## What the tracker ignores, and what it generates

- Ignored: `work-item-template/`, any folder whose name starts with `_` or `.`,
  and any record whose title is still `<Work item title>`.
- Generated by `toolkit work sync`: `DASHBOARD.md`. State kept by `toolkit work`:
  `.toolkit-state.json` (the ID-to-path map and the highest ID used). Never edit
  either by hand.
- Change frontmatter fields (stage, status, parent, waiting on, approvals) only
  with `toolkit work` commands. Body sections may be edited directly or with
  `toolkit work edit`; the hook checks the record after each edit.
- Keep any other files the owner put in an item folder.
