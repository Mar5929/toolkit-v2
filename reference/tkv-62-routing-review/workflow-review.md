With simulated read access, it reads the configured records through the installed Notion access procedure and checks approval, implementation, supersession and processing separately. It confirms the four fixture claims from their actual record homes. With no read access, the same claims are checked against supplied full records, stating that evidence source. With neither readable records nor supplied evidence, they remain Unchecked. A supplied stale Current state alone does not verify them. A claim that a runtime test passed still remains Unchecked without command output.

This resolves the earlier verifier gap without changing its read-only boundary. The procedure can use supported memory/tracker tools but still cannot write, run builds/tests, or approve content. Its goal-source rule now accepts authoritative wiki records, so a project-wide goal no longer needs an artificial DEC or local rule ID.
