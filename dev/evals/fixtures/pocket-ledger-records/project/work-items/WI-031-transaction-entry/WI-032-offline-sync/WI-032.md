## Requirements

### Requirement 1: Works with no signal

- **Original verbatim requirement:** "The app has to keep working with no signal and send everything later." (Mike, 2026-09-28, while splitting [[WI-031]])
- **Goal:** A user can keep logging in a place with no internet connection.

**Functional Requirements**

1. With no internet connection, a user can log a transaction, edit a transaction, and view the day's list.

**Acceptance Criteria:**

1. With the phone in airplane mode, a tester logs 3 transactions, edits one, and sees all 3 in the day's list.

### Requirement 2: Sends by itself when back online

- **Original verbatim requirement:** "1 minute is fine." (Mike, 2026-09-29, Q-02)
- **Goal:** What a user logged offline reaches the server without the user doing anything.

**Functional Requirements**

1. The app sends the transactions that were saved offline to the server within 1 minute of the connection returning.
2. The user does nothing to start the send.

**Acceptance Criteria:**

1. After the 3 offline transactions, the tester turns airplane mode off. The server shows all 3 within 1 minute.

### Requirement 3: No duplicates

- **Original verbatim requirement:** "Last time a bad connection made my phone send the same entry twice and I had two coffees in the list." (Mike, 2026-09-29, Q-01)
- **Goal:** A send that is interrupted never leaves a transaction on the server twice.

**Functional Requirements**

1. Each transaction reaches the server exactly once, even when a send is interrupted and tried again.

**Acceptance Criteria:**

1. The tester cuts the connection in the middle of a send and restores it. The server holds each transaction once.

### Requirement 4: The latest edit wins

- **Original verbatim requirement:** "Most recent wins. Don't bother the user." (Mike, 2026-09-30, Q-03)
- **Goal:** Two edits of one transaction on two phones end in one clear result.

**Functional Requirements**

1. When one transaction was edited on two phones before either phone synced, the app keeps the most recent edit and discards the other.
2. The app does not ask the user which edit to keep.

**Acceptance Criteria:**

1. The tester edits one transaction on two phones while both are offline, then syncs both. The server holds the later edit.
