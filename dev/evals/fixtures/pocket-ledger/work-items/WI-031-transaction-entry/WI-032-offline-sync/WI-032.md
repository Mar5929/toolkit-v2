### Starting request

"The app has to keep working with no signal and send everything later." (Mike, 2026-09-28, while splitting [[WI-031]].)

### Agreed goal

Transactions can be logged, changed, and viewed with no internet, and they reach the server by themselves when the connection returns.

### Active requirements

#### R-01 — Works with no signal

**Status:** Refining  
**Applies to:** A user whose phone has no internet connection.  
**Required behavior:** Logging, editing, and viewing transactions all work with no internet connection.  
**Boundaries and exceptions:** None identified.  
**Acceptance check:** With the phone in airplane mode, a tester logs 3 transactions, edits one, and sees all 3 in the day's list.  
**Decision record:** Source: Starting request and `references/2026-09-29-signal-notes.md`. Q-01.  
**Open questions:** None.

#### R-02 — Sends by itself when back online

**Status:** Refining  
**Applies to:** Transactions saved while the phone had no internet.  
**Required behavior:** Transactions saved offline are sent to the server without the user doing anything, within 1 minute of the connection returning.  
**Boundaries and exceptions:** None identified.  
**Acceptance check:** After the 3 offline transactions, the tester turns airplane mode off. The server shows all 3 within 1 minute.  
**Decision record:** Q-02, answered 2026-09-29.  
**Open questions:** None.

#### R-03 — No duplicates

**Status:** Refining  
**Applies to:** Every transaction that is sent to the server.  
**Required behavior:** Each transaction reaches the server exactly once, even when a send is interrupted and tried again.  
**Boundaries and exceptions:** None identified.  
**Acceptance check:** The tester cuts the connection in the middle of a send and restores it. The server holds each transaction once.  
**Decision record:** Q-01, from the notes in `references/2026-09-29-signal-notes.md`.  
**Open questions:** None.

#### R-04 — The latest edit wins

**Status:** Refining  
**Applies to:** A transaction edited on two phones before either phone has synced.  
**Required behavior:** The most recent edit is kept and the other is discarded. The user is not asked.  
**Boundaries and exceptions:** None identified.  
**Acceptance check:** The tester edits one transaction on two phones while offline, then syncs both. The server holds the later edit.  
**Decision record:** Q-03, answered 2026-09-30.  
**Open questions:** None.

### Acceptance

This work item can be accepted when:

1. R-01 to R-04 pass their acceptance checks on a real iPhone.
2. A tester has run the full offline test: log, edit, reconnect, and confirm on the server.
