+# Sync server
+
+This file records how the sync server works today. Tomas Lindqvist builds and hosts the sync server, and its code is in his repository `pocket-ledger-server`. Nobody on this project has tested what this file says: every fact below is what Tomas wrote.
+
+## What this area does today
+
+The sync server stores each user's transactions and computes the monthly totals (`PROJECT.md`, "Systems and environments"). The Pocket Ledger iPhone app is its only client.
+
+## Components
+
+| Component | Role | Where it is | Evidence |
+| --- | --- | --- | --- |

+
+## Data and flow
+
+Not recorded yet.
+
+## How it runs
+
+- The server accepts at most 60 requests a minute from one phone. (SRC-002)
+- When a phone sends more, the server answers with HTTP status 429 and drops the request. The server does not queue the request, so the phone must send it again. (SRC-002)
+- The 429 answer has no `Retry-After` header. The phone must wait a full minute by itself before it sends again. (SRC-002)
+- Tomas set the limit up on the first day of the server, and it is live on production. (SRC-002)
+- Tomas supports the server and decides how it is built and hosted. (`PROJECT.md`, "People and ownership")
+
+## Known gaps
+
+- Nobody on this project has seen the limit work. Mike can read the production logs, and has no sign-in to the staging server yet (PT-01).
+- SRC-002 does not say whether one request can carry several transactions. If one request carries one transaction, a phone can send at most 60 transactions a minute.
+- SRC-002 does not say whether the limit counts every request from the phone, or only the requests that send transactions.
+- SRC-002 does not say whether the staging server has the same limit.
+- SRC-002 does not say how the server tells one phone from another, or whether the minute starts with the first request or runs on the clock.
+- Tomas can confirm each of these.
+
+## Last verified
