No, the acceptance check for the no-duplicates requirement (WI-032, R-03) is not good enough yet. It reads: "The tester cuts the connection in the middle of a send and restores it. The server holds each transaction once."

It has three gaps:

- **It does not say how to count "once".** With your ID rule, the check can now be exact: one server record for each transaction ID, and no ID missing.
- **A connection cut by hand rarely hits the moment that makes a duplicate.** A duplicate happens only when the server has saved the send but its confirmation never reaches the phone, so the phone sends again. One cut at a random moment will usually pass even when the fault is there.
- **It checks only the server.** Your original problem was "two coffees in the list", which is the day's list on the phone.
