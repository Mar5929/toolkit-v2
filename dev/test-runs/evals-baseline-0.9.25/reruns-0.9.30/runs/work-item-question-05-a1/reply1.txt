The goal as I understand it: a user can see in the day's list which transactions have not reached the server yet.

What Requirement 5 says now:

- In the day's list, a transaction that the server does not have yet shows a small "not synced" badge.
- The badge goes away when the server has the transaction, and the user does nothing to remove it.
- The check: in airplane mode a tester logs a transaction and sees the badge. With airplane mode off, the server shows the transaction within 1 minute and the badge is gone.

Your request leaves one case open. Requirement 1 lets a user edit a transaction with no signal, so the server can hold a transaction while its latest change has not gone up.

Q-05: Does the "not synced" badge also show on a transaction that the server already has, when the user changed it and the change has not reached the server yet?
Recommended: yes, because the server then still holds the old amount, and the user cannot see that without the badge.
Watch out: the badge then means "something here has not gone up", for a new transaction and for a change alike, and the user cannot tell the two cases apart.
Not yet covered: a deleted transaction. Whether a user can delete at all is still open in WI-031 (Q-05 there), so I left that case out for now.
