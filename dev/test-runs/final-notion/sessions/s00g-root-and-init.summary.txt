## What the focus is for

The current focus is the first thing the next session reads: the session
briefing includes it. It says what is happening now and where the next
session starts. It never repeats the tracker: a work item's status, tasks,
and history stay in the work item.

| Backend | Where the focus lives |
| --- | --- |
| Built-in | `.memory/CURRENT_FOCUS.md` in the main checkout |
| Hindsight | The document `focus` in the project's bank |
| Notion | The "Current focus" page under the project's page |

The same commands read and save it in every backend. Never edit the file or
the page by hand.

## The format

The model's format: a `# Current focus` title line, a `Last updated:` line,
then exactly four `##` sections in this order, under 50 lines in total.

```markdown
# Current focus

Last updated: <YYYY-MM-DD>, <source>, <person or agent>

## Now

## Waiting on the owner

## Untracked to-dos

## Next session starts with
```

## Look before the first Git write

Other sessions may work in the same repository at the same time. Before the
first Git write in a session, run each of these on its own:

```text
git worktree list
git status
git remote
```

- `git remote` prints nothing: the project has no remote. Read "A project
  with no remote" below before any fetch, pull, push, or pull request.
- An unknown worktree, a branch that moved, or a change this session did not
  make means another session is working. Do not change it. Tell the owner.
- The shared primary checkout is the first entry `git worktree list` prints.
  In it, never switch branches, reset, rebase, or stash.
- Never commit, push, rebase, or delete another session's branch, and never
  commit its uncommitted changes, even when they look finished.
